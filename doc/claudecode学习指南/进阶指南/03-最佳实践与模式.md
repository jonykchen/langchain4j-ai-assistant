# 03 - 最佳实践与模式

> 经过验证的高效工作模式，帮你规避常见陷阱。

## 任务描述最佳实践

### 好的描述 vs 差的描述

| 差的描述 | 好的描述 |
|----------|----------|
| 优化代码 | 优化 UserService#getUserById 方法，当前有 N+1 查询问题，使用 JOIN FETCH 解决 |
| 修复 bug | 修复登录页面的表单验证 bug，点击提交时没有校验手机号格式 |
| 加个功能 | 在商品详情页添加收藏功能，需要登录后才能收藏，收藏状态要持久化 |
| 重构一下 | 把 OrderService 拆分成 OrderCreateService 和 OrderQueryService，保持接口不变 |

### 任务描述要素

```markdown
✅ 完整的任务描述包含：

1. 【做什么】具体的改动内容
2. 【在哪里】涉及的文件或模块
3. 【为什么】当前的背景或问题
4. 【怎么做】期望的解决方向（可选）
```

## 常用工作模式

### 模式一：TDD 工作流

```
1. 描述需求，让 Claude 先写测试
2. 确认测试用例覆盖所有场景
3. 让 Claude 实现代码
4. 运行测试验证
5. 让 Claude 重构优化
6. 再次运行测试确保通过
```

**示例对话：**

```
用户：为积分服务编写单元测试，需要覆盖：
- 积分获取
- 积分消费
- 积分过期
- 余额不足异常

Claude：[生成测试代码]

用户：好的，现在实现这些功能让测试通过

Claude：[实现代码]

用户：运行测试

Claude：[执行 mvn test，报告结果]
```

### 模式二：渐进式重构

```
用户：OrderService 有 800 行代码，太长了，请分步骤重构：

Step 1: 分析职责，列出可以拆分的功能模块
Claude：[输出分析结果]

用户：就按这个拆分，先提取订单创建相关的方法

Claude：[创建 OrderCreateService]

用户：继续提取订单查询相关的方法

Claude：[创建 OrderQueryService]
```

### 模式三：代码审查流程

```
用户：审查 src/service 目录的代码，重点关注：

1. 安全漏洞
2. 性能问题
3. 代码规范

输出格式：按严重程度排序，给出具体文件和行号

Claude：[输出审查报告]

用户：修复严重和高危问题

Claude：[逐个修复]
```

### 模式四：问题诊断流程

```
用户：生产环境 OOM，请帮我诊断：

1. 检查 JVM 参数配置
2. 分析代码中的内存泄漏风险
3. 审查大对象创建
4. 检查缓存策略

相关文件：
- 启动脚本：deploy/start.sh
- 缓存配置：src/config/RedisConfig.java
- 大数据查询：src/repository/*

Claude：[输出诊断报告和优化建议]
```

## 常见问题处理

### 问题一：Claude 理解错误

**症状：** Claude 修改了错误的代码或理解偏了

**解决方案：**

```markdown
不是这里，我要改的是 src/service/UserService.java，不是 UserController.java。

具体是这个方法：

```java
public User findById(Long id) {
    return userMapper.selectById(id);
}
```

我想把它改成返回 Optional<User>。
```

### 问题二：任务太复杂

**症状：** Claude 给出的方案太复杂或卡住

**解决方案：**

```
这个任务太大了，我们分步来：

Step 1: 先只做数据库表设计
Step 2: 再做实体类和 Mapper
Step 3: 然后做 Service 层
Step 4: 最后做 Controller

现在开始 Step 1
```

### 问题三：Claude 不遵循规范

**症状：** 生成的代码不符合项目风格

**解决方案：**

```
这个代码风格不对，参考这个示例：

```java
// 项目中的标准写法
@Override
public Result<User> getUser(Long id) {
    User user = userService.findById(id);
    if (user == null) {
        return Result.error("用户不存在");
    }
    return Result.success(user);
}
```

按照这个风格重写。
```

### 问题四：忘记之前的约定

**症状：** 会话重启后 Claude 忘记了项目约定

**解决方案：**

1. 把重要约定写入 `CLAUDE.md`
2. 使用记忆系统保存
3. 新会话开始时重申关键信息

```
这是一个新会话，让我先说明项目背景：
- 使用 MyBatis-Plus
- 统一响应格式 Result<T>
- JWT 认证
```

## 性能优化技巧

### 减少 Claude 的搜索步骤

**低效方式：**

```
优化登录功能
```

Claude 需要搜索整个项目找到登录相关代码。

**高效方式：**

```
优化 src/controller/AuthController.java 的 login 方法，
当前响应时间 2 秒，需要优化到 500ms 以内
```

Claude 直接读取指定文件开始分析。

### 利用记忆避免重复解释

每次会话都要解释项目背景，很浪费：

```markdown
# 写入 MEMORY.md

## 项目背景
电商后台，Spring Boot + Vue 3

## 核心约定
- 统一响应格式 Result<T>
- JWT 认证
- MyBatis-Plus

## 关键路径
- 入口：Application.java
- 配置：application.yml
```

下次会话 Claude 自动知道这些信息。

### 并行处理独立任务

```
这三个任务是独立的，请并行处理：

1. 分析 src/auth 的安全性
2. 审查 src/api 的性能
3. 检查 src/config 的配置

完成后汇总结果。
```

## 团队协作建议

### 共享 CLAUDE.md

把 `CLAUDE.md` 纳入版本控制，团队成员共享项目上下文。

### 共享记忆文件

```
memory/
├── MEMORY.md           # 团队共享的项目记忆
├── patterns.md         # 团队编码模式
└── conventions.md      # 团队编码规范
```

### 代码审查集成

让 Claude 参与代码审查流程：

```
审查这个 PR 的改动，检查：
1. 是否有测试
2. 是否符合编码规范
3. 是否有安全风险
```

## 安全注意事项

### 不要提交敏感信息

```markdown
❌ 不要写入 CLAUDE.md 或记忆文件：
- 数据库密码
- API 密钥
- JWT 密钥
- 证书文件

✅ 使用环境变量：
- .env 文件（不提交）
- application-{profile}.yml（敏感部分用环境变量）
```

### 权限配置

```json
// settings.json
{
  "permissions": {
    "deny": [
      "Read(**/.env)",
      "Read(**/secrets/**)",
      "Read(**/credentials.json)"
    ]
  }
}
```

## 小结

最佳实践要点：

1. **任务描述** - 明确、具体、给上下文
2. **工作模式** - TDD、渐进重构、代码审查、问题诊断
3. **问题处理** - 提供示例、分步执行、明确规范
4. **性能优化** - 减少搜索、利用记忆、并行处理
5. **团队协作** - 共享配置、统一规范
6. **安全意识** - 不存敏感信息、配置权限
